# Papers: Plain files as agent knowledge

This group holds the papers behind [plain files as agent knowledge](../trends/plain-file-knowledge.md): knowledge kept as Markdown pages that a model writes and a person can read, instead of rows, vectors or graph nodes. The line of work has no founding paper. Its origin is a gist, "LLM Wiki", created under the account `karpathy` on 20260404 at 16:25 UTC [1][2]. An arXiv API query for the phrase "LLM wiki" in the 13 days from 20260404 to 20260416 returns two records, both submitted on 20260413 [14]; the archive reached the same finding earlier [13]. A query for "Karpathy" in the same window adds a third record, also from 20260413, an architecture paper that names Karpathy's knowledge base as one of eight points it gathers [14][15]. Both queries search record metadata (title, abstract, comments), not full texts, so they show what the early records say, not every early paper [14][16]. One paper is listed as fundamental, the first reference implementation with a measurement. No other paper passed a test, so the group stays at one. The preregistered comparison with vector [RAG](../index/retrieval-augmented-generation.md) is cited by one independent later paper as corroboration and extended only by its own author; the largest study of files as [agent memory](../index/agent-memory.md) claims to be the first, although earlier designs already keep agent memory in files, and no later paper read cites it (see Further reading). The paper listed is under seven months old and has no usable citation count, so it does not pass the "widely built on" test; its claim rests on the arXiv timestamps.

## Knowledge Compounding (2026)

*Knowledge Compounding: An Empirical Economic Analysis of Self-Evolving Knowledge Wikis under the Agentic ROI Framework.* Shuide Wen, Beier Ku (2 authors). No venue stated; arXiv preprint. First version 20260413. https://arxiv.org/abs/2604.11243 [3].

**Why fundamental:** Origin of the paper line, not of the approach, which the gist introduced. It is the earliest record in the arXiv API queries above: v1 at 09:50:29 UTC on 20260413, against 12:05:30 UTC for the architecture paper and 20:22:53 UTC for [Memory as Metabolism](#further-reading) [3][4][14], nine days after the gist [2]. The queries read metadata only, so this is priority among records that use these words, not a proof over all papers [16]. A further search made for this page, for the phrases "LLM wiki", "LLM-maintained wiki" and "compiled wiki" in records submitted before 20260413, returned none, so no earlier arXiv record uses them [18]. The authors call it "the first complete industrial-grade reference implementation" of the gist's pattern, about 200 lines of C# and plain Markdown files [3][5]; that is the authors' claim. Citation count: unstated.

**Idea:** once a persistent wiki exists, the cost of a query is no longer independent of earlier queries, so cost is a function of how much the wiki already covers [5]. In a four-query run on the authors' own system (first-party), the wiki-building regime used 47K tokens and left one synthesis page and five new entity facts [5]. *Reading:* the arXiv abstract still says 47K against 305K for "a matched RAG baseline", an 84.6% saving [3]; v1 of the PDF says the same [6]. The current PDF (v2) says the opposite: a chunk-RAG baseline, with values estimated from the standard pipeline parameters, is cheapest at 13.6K (an appendix check against a measured query puts it near 14.6K), and 305K is a long-context baseline [5]. Cite the PDF, not the abstract. It names [Mem0 (2025)](./agent-memory.md) and [A-MEM (2025)](./agent-memory.md) as examples of memory systems that break the assumption that each task's cost is independent [5]. It extends the Agentic ROI framework of Liu et al. (2026), a position paper that has no section in this chapter [3][17], and names the gist as the pattern it implements (not a paper) [5].

**Relations:** Builds on: also: Liu et al. (2026), a position paper.

**Read:** full text of v2 and v1 (PDF text), abstract page; 20261102 20:43 UTC. Re-read for this revision (v2 PDF: abstract, sections 1.1, 1.3, 5.1, appendix D; abstract page): 20261102 20:54 to 20:55 UTC [3][5][6].

## Further reading

- Vector RAG vs LLM Wiki (Cochran, 2026), https://arxiv.org/abs/2605.18490 : "Single-Round Vector RAG vs an LLM-Compiled Wiki: A Preregistered Comparison on a Small Multi-Domain Research Corpus"; the same model answered 13 questions over 24 papers with a vector RAG pipeline and with a wiki it had compiled and a tool-using agent browsed, and two blinded judges scored the answers; the wiki was much better at connecting findings across papers, but its edge in organization fell below the registered threshold and it used about 21 times more tokens per query, so the paper reports that no break-even point exists; a decomposition variant of RAG closed most of the synthesis gap. The verdict is tied to serving the wiki to an agent that browses it for up to 30 turns. One author, "We do not claim priority"; the wiki run began 77 minutes before the registration timestamp, which the paper discloses; v1 20260518, v3 20261002 corrects an error [7][8]. Moved from the fundamental list: the later papers read treat it as corroboration or extend it. The RAGFlow-team study cites it as "a preregistered comparison" that "found exact search approaching an LLM-compiled wiki", and the author's own preregistered ablation takes the wiki architecture as fixed [11][19].
- Filesystem-Based Memory (Zhou, Yu, Wei and 8 others, 2026), https://arxiv.org/abs/2607.26637 : "Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability" (11 authors; affiliations at UC San Diego, UIUC, UC Merced, Texas A&M and Adobe Research); three roles (management, search, execution agents) around one directory tree of Markdown files, tested on [LoCoMo](../benchmarks/locomo.md), PersonaMem, REALTALK and ALFWorld while varying memory shape, scale, tool harness and model strength; organized stores "roughly halve retrieval cost" where material is large, but organization erodes for all but the strongest management agent, and no agent converts organization into better answers; v1 20260729 [9][10]. Moved from the fundamental list: it presents "the first systematic exploration of filesystem-based memory for LLM agents" (the authors' claim), but an arXiv search made for this page returned earlier records that build agent memory or context on files, among them ByteRover (20260402, whose abstract describes "a file-based knowledge graph"), Interpretable Context Methodology (20260317, folder structure with plain Markdown files) and FS-Researcher (20260202, a file-system-based dual-agent framework), so only "first systematic study" remains, which titles and abstracts can neither confirm nor refute; no later paper read cites it [18][19].
- Memory as Metabolism (Miteski, 2026), https://arxiv.org/abs/2604.12034 : a design and governance profile for single-user wikis, v1 20260413; the abstract reports no measurement [4][11].
- Progressive Disclosure for LLM-Maintained Wiki Knowledge Bases (Cochran, 2026), https://arxiv.org/abs/2607.04576 : a preregistered ablation on a 709-page wiki; quality held, cost fell [11].
- WikiSkill (Tang and others, 2026), https://arxiv.org/abs/2608.27454 : a wiki that co-evolves with agent skills; v1 20260827; six authors, affiliations unstated on the abstract page [11].
- Everything is Context (Xu and others, 2025), https://arxiv.org/abs/2512.05470 : a file-system abstraction for context engineering, v1 20251205, before the gist [11].
- WiCER (Huerta, 2026), https://arxiv.org/abs/2605.07068 : blind compilation lost facts (53 to 60% catastrophic failures); an iterative fix recovers 80% of lost quality [12].
- Context as Infrastructure (Yu and others, 2026), https://arxiv.org/abs/2610.41172 : a BM25 and grep harness answers 85% of BrowseComp-Plus; structural artifacts gave no detectable gain on FRAMES [12].
