# Papers: Agentic graph retrieval

This group holds the fundamental papers behind the trend [Agentic graph retrieval](../trends/learned-graph-traversal.md), in which a model, not a fixed pipeline, chooses which part of a [knowledge graph](../index/knowledge-graph.md) to read next, over several turns, and in the newest work is trained for the job with [reinforcement learning](../index/reinforcement-learning.md). Two papers of 2023 set up the walk, one by prompting and one by fine-tuning; three of 2025 train it, over text, a graph or a memory store. GraphRAG-R1, a concurrent paper on training the graph walk, is in the further reading because no test could be shown for it. No blog post or gist was found as the origin of this line of work in the sources read, so the origin is unstated beyond the papers below.

## Think-on-Graph (2023)

**Paper:** "Think-on-Graph: Deep and Responsible Reasoning of Large Language Model on Knowledge Graph", Jiashuo Sun, Chengjin Xu, Lumingyuan Tang and 6 others (9 authors in total); ICLR 2024 (the PDF header and the arXiv comment); first version 20230715; <https://arxiv.org/abs/2307.07697> [3][4].

**Why fundamental:** Widely built on, and an origin in a narrow sense. It has 373 citations in Semantic Scholar (read 20261102 20:20 UTC, carried over) [13], below the 500 that the candidate pool applied (a working threshold of that pool, not a project rule), but later papers read build on it or test against it: Think-on-Graph 2.0 extends it, Reasoning on Graphs describes it, with KG-Agent, as an LLM that interacts with the graph by prompting, and GNN-RAG lists it with three model sizes in its results tables [37]; AutoSchemaKG (in [Building knowledge graphs with LLMs](./llm-kg-construction.md), further reading) and GraphRAG-R1 (further reading here) run it as a baseline, GraphRAG-R1 calling it "a representative GraphRAG method" [10]. The narrow origin is beam search over relations and then entities, run by a prompted model, under a named paradigm. Its abstract introduces the "LLM ⊗ KG" paradigm, which "treats the LLM as an agent to interactively explore related entities and relations on KGs" [3]. It is not the first iterative LLM-over-graph method. StructGPT (first version 20230516, two months earlier) has the model call graph interfaces again and again, in an "Iterative Reading-then-Reasoning" loop [17]. The paper knows it: it lists StructGPT as a baseline and calls it "a special case of ToG", while it says the other prompt-augmenting methods follow "a fixed pipeline" [4]. That framing is the authors' own. An arXiv search made for this page (titles and abstracts of records before 20230715; source 37) returned StructGPT, Graph-ToolFormer (20230410) and "Complex Logical Reasoning over Knowledge Graphs using Large Language Models" (20230502) among the 2023 records on language models and structured data; only StructGPT was read, so the narrow origin is not contradicted by the records read, and not proven. ToG is the prompted precursor of this group: nothing is trained [3].

**Idea:** the model names the topic entities in the question, then repeats two steps. In exploration it searches the graph by beam search, first over relations and then over entities, and scores and prunes the candidates at each step. In reasoning it decides whether the best paths are enough to answer [4]. Width and depth are 3 by default, and the graph is Freebase or Wikidata [4]. First-party results: best result on 6 of 9 datasets with GPT-4, and a 70B Llama-2 ahead of GPT-4 chain-of-thought on CWQ and WebQSP [3][4]. It cites [ReAct (2022)](./agentic-search.md) twice and builds nothing on it: once for the "dynamic reasoning ability" of its agent, once in related work as an example of using outside sources [4]. It runs StructGPT (2023, no section here), the earlier iterative method that it counts as a special case of itself, as a baseline [4][17], and is scored on [WebQSP](../datasets/webquestionssp.md) ([benchmark page](../benchmarks/webquestionssp.md)), [CWQ](../datasets/complexwebquestions.md), [GrailQA](../datasets/grailqa.md) and [SimpleQuestions](../datasets/simplequestions.md), among nine sets [4].

**Relations:** Evaluates: also: StructGPT.

StructGPT: arXiv abstract only, 21:00 UTC [17].

## KGP (2023)

**Paper:** "Knowledge Graph Prompting for Multi-Document Question Answering", Yu Wang, Nedim Lipka, Ryan A. Rossi and 3 others (6 authors in total); AAAI 2024 (from the copyright line and the supplement file name in the v3 PDF; the arXiv page names no venue); first version 20230822; <https://arxiv.org/abs/2308.11730> [1][2].

**Why fundamental:** Origin, in a narrow and first-party sense: it names and trains an "LLM-based KG traversal agent", a fine-tuned model that picks the next node among the neighbours of the nodes already visited in a graph built beforehand [2][34]. What is new is the walk over a pre-built graph, not trained next-step selection. MDR, its second-best baseline, already fine-tunes an encoder to predict the next supporting fact from the passages retrieved so far [2]. The paper claims to fill a gap, saying "few works explore this paradigm" in multi-document question answering, and does not claim to be first [34]. An arXiv search made for this page (titles and abstracts of records before 20230822; source 37) found no earlier record on traversing a graph of passages with a language model for multi-document question answering; its only match is a record of 2019 on local knowledge graph construction for multi-document input, seen by title. Think-on-Graph is about five weeks older but trains nothing [3]. It has 384 citations (Semantic Scholar, read 20261102 20:20 UTC, carried over) [13], under the pool's 500 threshold; GraphRAG-R1 (further reading) later ran it as a baseline [10], and the other later papers read (Reasoning on Graphs, GNN-RAG) do not cite it [37].

**Idea:** KGP builds a graph over many documents: nodes are passages, pages or tables, and edges join passages that share keywords or have similar embeddings [2]. A language model fine-tuned to predict the next supporting passage from those already visited walks it: from TF-IDF seeds it writes what the next evidence should say and visits the neighbour that matches best, until a passage budget is spent [2]. The "knowledge graph" is a similarity graph of passages, not extracted entities and relations [2]. First-party: with a 0.7B T5 as walker, [HotpotQA](../datasets/hotpotqa.md) F1 is 66.77 against 65.16 for MDR, but IIRC F1 is 41.54 against 43.47, so the text's "Top-1" does not hold in every column [2]. It runs [DPR (2020)](./foundations.md), [IRCoT (2022)](./agentic-search.md) and MDR (Xiong et al. 2020, no section here) as baselines, on [HotpotQA](../datasets/hotpotqa.md) ([benchmark page](../benchmarks/hotpotqa.md)), [2WikiMultiHopQA](../datasets/2wikimultihopqa.md) ([benchmark page](../benchmarks/2wikimultihopqa.md)) and [MuSiQue](../datasets/musique.md) ([benchmark page](../benchmarks/musique.md)), plus IIRC and PDFTriage (no section here) [2].

**Relations:** Evaluates: [Karpukhin et al. (2020)](./foundations.md), [IRCoT (2022)](./agentic-search.md); also: MDR (Xiong et al. 2020).

**Read:** full text of the arXiv PDF (v3), text extracted, pages 1 to 8; the supplement was not read. 20261102 20:42 UTC; the MDR baseline passage re-read in the PDF and the traversal-agent passages in the arXiv HTML rendering of v3 at 21:00 to 21:01 UTC [1][2][34].

## Search-R1 (2025)

**Paper:** "Search-R1: Training LLMs to Reason and Leverage Search Engines with Reinforcement Learning", Bowen Jin, Hansi Zeng, Zhenrui Yue and 5 others (8 authors in total); COLM 2025 (the PDF header; the arXiv comment says "31 pages"); first version 20250312; <https://arxiv.org/abs/2503.09516> [5][6].

**Why fundamental:** Widely built on, with the plain-text baseline role. Its abstract says the model "learns to autonomously generate (multiple) search queries during step-by-step reasoning" with a "simple outcome-based reward function" [5]. It is not alone: R1-Searcher's first version is five days earlier (20250307), so Search-R1 is the chosen representative and no origin is claimed [15]. It has 1,742 citations (Semantic Scholar, read 20261102 20:20 UTC, carried over), over the pool's 500 [13]. Graph-R1 cites it among its RL agents and runs it as its main text-only baseline, and GraphRAG-R1 (further reading) names it as earlier RL work on RAG [8][10]. It searches text, not a graph.

**Idea:** the model writes its search query between special tags, the retrieved passages are put into its context, and it continues, for several turns, until it answers [6]. Training uses PPO or GRPO with a reward that checks only the final answer, and retrieved tokens are masked out of the loss [5][6]. The retriever is E5 over the 2018 Wikipedia dump of DPR, and training merges the NQ and HotpotQA training sets [6]. First-party, average relative gain over RAG baselines on seven datasets, with two values for the 7B model in the same paper: 41% in the arXiv listing abstract and in the introduction, 24% in the v5 PDF abstract and in the results section; the 3B gain is 20% everywhere [5][6]. This page does not decide between 41% and 24%; the table was not recomputed. It answers the prompted search of [ReAct (2022)](./agentic-search.md) and [IRCoT (2022)](./agentic-search.md), which its related work groups among methods that "use prompting" to guide search calls [6]. It runs [RAG (Lewis et al., 2020)](./foundations.md) and IRCoT as baselines, on [NQ](../datasets/natural-questions.md) ([benchmark page](../benchmarks/natural-questions.md)), [HotpotQA](../datasets/hotpotqa.md) ([benchmark page](../benchmarks/hotpotqa.md)), [TriviaQA](../datasets/triviaqa.md), [PopQA](../datasets/popqa.md), [2WikiMultiHopQA](../datasets/2wikimultihopqa.md) ([benchmark page](../benchmarks/2wikimultihopqa.md)) and [MuSiQue](../datasets/musique.md) ([benchmark page](../benchmarks/musique.md)), and Bamboogle (no page here) [6].

**Relations:** Answers: [ReAct (2022)](./agentic-search.md), [IRCoT (2022)](./agentic-search.md). Evaluates: [Lewis et al. (2020)](./foundations.md), [IRCoT (2022)](./agentic-search.md).

## Graph-R1 (2025)

**Paper:** "Graph-R1: Towards Agentic GraphRAG Framework via End-to-end Reinforcement Learning", Haoran Luo, Haihong E, Guanting Chen and 8 others (11 authors in total); ICML 2026; first version 20250729 (v2 20260602); <https://arxiv.org/abs/2507.21892> [7][8].

**Why fundamental:** Widely built on in the papers read, with an origin claim that is contested. Its abstract calls it "the first agentic GraphRAG framework via end-to-end reinforcement learning (RL)", and says [GraphRAG](../index/graphrag.md) still has "fixed one-time retrieval" [7]. "First" is the authors' claim, and two records qualify it: DynaSearcher (arXiv 2507.17365, 20250723, six days earlier) is a search agent that uses dynamic knowledge graphs and is trained with multi-reward RL [37], and GraphRAG-R1 (20250731, further reading) claims the same move two days later [9][10]; this page does not rest on origin. Later papers read take it up: HyperGraphPro discusses it throughout as the RL-based GraphRAG framework (21 mentions), PathRouter says it extends Search-R1 and R1-Searcher to graph-structured knowledge and compares with it, Search-on-Graph-R1 names it as the GraphRAG-setting counterpart of its own method, and RAGSearch (further reading in [Graph-based RAG](./graph-based-rag.md)) runs it as one of two trained agents [37][16]. It has 64 citations (Semantic Scholar, read 20261102 20:20 UTC, carried over) [13], below the pool's 500 threshold.

**Idea:** a language model builds a knowledge [hypergraph](../index/hypergraph.md) once, with GPT-4o-mini, each edge holding an n-ary fact [8]. The agent then loops "think-retrieve-rethink-generate": it writes a query, gets facts through entity-based and direct hyperedge retrieval, and decides whether to query again or answer [8]. It is trained with [GRPO](../index/grpo.md) and a reward that adds a format part and an answer part [8]. First-party: average F1 57.82 against 46.19 for Search-R1 (Qwen2.5-7B), on 128 test questions per dataset [8]. It builds on [Search-R1 (2025)](./learned-graph-traversal.md), the baseline it improves [8], and answers [GraphRAG (2024)](./graph-based-rag.md) and its fixed retrieval [7]. It runs GraphRAG, [LightRAG](./graph-based-rag.md), [HippoRAG 2](./graph-based-rag.md) and [RAG (Lewis et al., 2020)](./foundations.md) as baselines, and compares with Search-R1 and R1-Searcher (2025, further reading) as its two main trained baselines [8][35], on [2WikiMultiHopQA](../datasets/2wikimultihopqa.md), [HotpotQA](../datasets/hotpotqa.md), [MuSiQue](../datasets/musique.md), [NQ](../datasets/natural-questions.md), [PopQA](../datasets/popqa.md) and [TriviaQA](../datasets/triviaqa.md) [8]. In RAGSearch, training-free GraphSearch workflows "generally outperform" it [16].

**Relations:** Builds on: [Search-R1 (2025)](./learned-graph-traversal.md). Answers: [GraphRAG (2024)](./graph-based-rag.md). Evaluates: [GraphRAG (2024)](./graph-based-rag.md), [LightRAG (2024)](./graph-based-rag.md), [HippoRAG 2 (2025)](./graph-based-rag.md), [Lewis et al. (2020)](./foundations.md); also: R1-Searcher (2025).

## Memory-R1 (2025)

**Paper:** "Memory-R1: Enhancing Large Language Model Agents to Manage and Utilize Memories via Reinforcement Learning", Sikuan Yan, Xiufeng Yang, Zuchao Huang and 10 others (13 authors in total); the arXiv record (v5) names no venue (Semantic Scholar lists the Annual Meeting of the ACL, unchecked); first version 20250827; <https://arxiv.org/abs/2508.19828> [11][12][14].

**Why fundamental:** Widely built on in the papers read, and an origin in a narrow sense. It has 246 citations (Semantic Scholar, read 20261102 19:47 UTC, carried over) [14], below the pool's 500 threshold, but later papers read take it up: Uni-Mem lists it among the training-based methods it compares with and runs it as a baseline, and MemComposer cites it as the use of RL to manage memory operations [37]. The narrow origin is the first reinforcement-learned manager of an external memory bank with ADD, UPDATE, DELETE and NOOP operations. This is the authors' claim, not independently established. The paper's contribution list says it is "the first RL framework for memory-augmented LLMs", while its related work says "among the first" [12][36]. Two earlier arXiv records already train memory handling with RL: MEM1 (first version 20250618) and MemAgent (20250703), which Memory-R1 does not mention [18][19][36]. They differ in what the memory is. In MEM1 the agent rewrites one compact "internal state" at each turn and drops the earlier text [18][20]. In MemAgent the model rewrites a fixed-length memory of 1,024 tokens as it reads a long text in segments [19][21]. Neither operates on a bank of separate entries, which is the narrow claim; whether that difference is deep, this page does not judge. An arXiv search made for this page (records before 20250827; source 37) also returned REMEMBERER (20230609), which updates an experience memory with reinforcement learning without changing the model's weights. Its place here is the technique, not a graph: Search-R1's recipe, a policy rewarded on task success, applied to what an [agent](../index/agent.md) stores.

**Idea:** two agents are tuned with PPO or GRPO. A Memory Manager picks ADD, UPDATE, DELETE or NOOP for each new dialogue turn; an Answer Agent filters the memories that RAG retrieves and reasons over them [11][12]. Training uses 152 [LoCoMo](../datasets/locomo.md) questions; MSC and [LongMemEval](../datasets/longmemeval.md) are zero-shot tests [12]. All results are first-party. The introduction calls Mem0 the most competitive baseline and the results section calls MemoryOS the strongest, yet in both blocks of Table 1 MemoryOS scores above Mem0 (overall F1 35.04 against 30.41, and 34.64 against 30.61). A supervised baseline trained on GPT-5 output scores higher still, so the RL gain is smaller (LLaMA overall F1 45.02 against 42.81) [12]. It adopts the operation set of [Mem0 (2025)](./agent-memory.md), names the RL search work of [Search-R1 (2025)](./learned-graph-traversal.md) as the success it builds on, and calls the memory control of [MemGPT (2023)](./agent-memory.md) and Mem0 heuristic [12]. It runs [A-MEM (2025)](./agent-memory.md) and Mem0 as baselines, on [LoCoMo](../benchmarks/locomo.md) ([dataset page](../datasets/locomo.md)) and [LongMemEval](../benchmarks/longmemeval.md) ([dataset page](../datasets/longmemeval.md)) [12].

**Relations:** Builds on: [Search-R1 (2025)](./learned-graph-traversal.md), [Mem0 (2025)](./agent-memory.md). Answers: [MemGPT (2023)](./agent-memory.md), [Mem0 (2025)](./agent-memory.md). Evaluates: [A-MEM (2025)](./agent-memory.md), [Mem0 (2025)](./agent-memory.md).

**Read:** full text of the arXiv PDF (v5), text extracted: abstract, introduction, setup and Table 1; appendices not read. 20261102 20:42 UTC; the contribution list and related work re-read in the arXiv HTML rendering of v5 at 21:00 UTC [11][12][36]. MEM1 and MemAgent: arXiv abstracts and the HTML introductions of v2, 21:00 to 21:02 UTC; method and results not read [18][19][20][21].

## Further reading

One line each; all are arXiv abstracts, read 20261102 between 20:45 and 20:46 UTC except the last three (21:00 UTC), each cited by its own source number. Citation counts are carried over from the retrieval candidate pool (Semantic Scholar, read 20261102 20:20 UTC) [13].

- GraphRAG-R1 (2025), <https://arxiv.org/abs/2507.23581>: "Graph Retrieval-Augmented Generation with Process-Constrained Reinforcement Learning", The Web Conference 2026; a modified GRPO lets the model call a retrieval tool mid-reasoning, with Progressive Retrieval Attenuation and Cost-Aware F1 as rewards and HippoRAG 2 as the retriever; first-party F1 on HotpotQA 38.00 against 27.52 for HippoRAG 2 and 26.82 for R1-Searcher; first version 20250731, two days after Graph-R1 and not citing it; 15 citations. Moved from the fundamental list: a concurrent second start of the move, and none of the four later papers read on RL for graph retrieval (HyperGraphPro, RANGER, Search-on-Graph-R1, PathRouter) cites it [9][10][13][37].
- GraphSearch (2025), <https://arxiv.org/abs/2509.22009>: a training-free six-module workflow with dual-channel (text and graph) retrieval; the counterpart that beats trained agents in RAGSearch [16][22].
- GraphWalker (2026), <https://arxiv.org/abs/2603.28533>: an agent trained on trajectories synthesised from random walks, then fine-tuned and given a light RL stage; COLM 2026 [23].
- PathRouter (2026), <https://arxiv.org/abs/2606.16409>: names "answer-path reward aliasing" in outcome-only RL and rewards evidence-path overlap too [24].
- Search-on-Graph-R1 (2026), <https://arxiv.org/abs/2607.18481>: SFT then RL for an 8B model that searches a live Freebase server [25].
- Reasoning on Graphs (2023), <https://arxiv.org/abs/2310.01061>: plans relation paths first, then retrieves them from the graph; ICLR 2024; 591 citations [13][26].
- Think-on-Graph 2.0 (2024), <https://arxiv.org/abs/2407.10805>: alternates graph retrieval and document retrieval, training-free; 113 citations [13][27].
- Search-o1 (2025), <https://arxiv.org/abs/2501.05366>: training-free agentic search for reasoning models; 497 citations [13][28].
- R1-Searcher (2025), <https://arxiv.org/abs/2503.05592>: two-stage outcome-based RL for search, five days before Search-R1; 324 citations [13][15].
- HyperGraphPro (2026), <https://arxiv.org/abs/2601.17755>: stepwise, progress-based rewards for hypergraph agents instead of outcome-only ones [29].
- RANGER (2026), <https://arxiv.org/abs/2610.28010>: a Transformer policy learns to walk a graph, and an LLM scores its paths to give the reward [30].
- Uni-Mem (2026), <https://arxiv.org/abs/2610.29671>: one RL policy learns both memory construction and retrieval [31].
- MemComposer (2026), <https://arxiv.org/abs/2610.21091>: learns which memories to include, how many and in what order [32].
- Is Complex Agentic Memory Always Needed? (2026), <https://arxiv.org/abs/2610.30755>: a plain dense-retrieval baseline ranks first in six of seven settings against agentic memory systems [33].
- StructGPT (2023), <https://arxiv.org/abs/2305.09645>: the earlier iterative reading-then-reasoning method over graphs, tables and databases that Think-on-Graph counts as a special case of itself; EMNLP 2023 [17].
- MEM1 (2025), <https://arxiv.org/abs/2506.15841>: an end-to-end RL agent that keeps constant memory by rewriting one internal state each turn [18].
- MemAgent (2025), <https://arxiv.org/abs/2507.02259>: an RL-trained agent that reads a long text in segments and overwrites a fixed-length memory; ICLR 2026 oral [19].
