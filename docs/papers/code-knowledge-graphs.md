# Papers: Code graphs for coding agents

This group holds the fundamental papers behind the trend [Code graphs for coding agents](../trends/code-knowledge-graphs.md), in which a parser turns a repository into a [code graph](../index/code-graph.md) of definitions, calls and imports that a coding [agent](../index/agent.md) queries instead of reading files and searching them with [grep](../index/grep.md). The line of work did not start with a paper. Its earliest dated source read here is a blog post of 20231022 in which Aider describes a repository map built with [tree-sitter](../index/tree-sitter.md) and cut to a token budget by a graph-ranking algorithm; the post says the map replaced an earlier one built with ctags, so the idea is older than the post [1]. Two papers of 2024 put a graph behind an agent. The three papers of 2026 listed in the first edition, a system and two tests of whether the graph helps, are in the further reading: none of them passes a test on the sources read. No citation threshold is applied to this group (the sibling group [Graph-based RAG](./graph-based-rag.md) uses 500 for a much older field), and each section names the test it passes.

## CodexGraph (2024)

**Paper:** "CodexGraph: Bridging Large Language Models and Code Repositories via Code Graph Databases", Xiangyan Liu, Bo Lan, Zhiyuan Hu and 5 others (8 authors in total); NAACL 2025, Long Papers, April 2025 (the arXiv comment still says "work in progress") [10][2]; first version 20240807; <https://arxiv.org/abs/2408.03910>.

**Why fundamental:** Origin, in a narrow sense, narrowed by a search. It is the earliest paper found in this chapter's search in which a language-model agent writes queries against a graph database built from a repository, so that it can "construct and execute queries" for "code structure-aware context retrieval" [2]. An arXiv search made for this page (titles and abstracts of records before 20240807; source 13) returned two earlier repository-graph papers that do not do this: Alibaba LingmaAgent (20240603), which condenses a repository into a knowledge graph that an agent explores with Monte Carlo tree search, and GraphCoder (20240611), which retrieves from a code context graph for code completion [13][5]; in neither does an agent write queries against a graph database. It has 114 citations in Semantic Scholar (read 20261102 19:47 UTC, carried over), given for context [8]. RepoGraph calls it concurrent work, and Codebase-Memory (further reading) cites it as exposing code graphs to agents "via graph database interfaces" [4][5].

**Idea:** static analysis extracts a graph of modules, classes, functions and their relations into Neo4j [3]. One agent writes a request in natural language, a second translates it into a [Cypher](../index/cypher.md) query, and the result goes back to the first [3]. The authors report "competitive performance", "especially when equipped with more advanced LLMs": with GPT-4o it beats retrieval baselines on CrossCodeEval Lite and EvoCodeBench and is comparable to AutoCodeRover on SWE-bench Lite, but with Qwen2 it scores below BM25 on CrossCodeEval exact match (5.00 against 15.50) [3] (first-party). It builds on [GraphRAG (2024)](./graph-based-rag.md): the introduction says it is "inspired by recent advances in graph-based RAG", citing Edge et al. first [3]. It answers similarity-based retrieval, which "often has low recall in complex tasks" [2]. It is scored on CrossCodeEval, SWE-bench and EvoCodeBench, which have no page here [3].

**Relations:** Builds on: [GraphRAG (2024)](./graph-based-rag.md).

**Read:** abstract, 20261102 20:48 UTC [2]; full text in HTML searched 20:48 to 20:53 UTC [3]; venue page 21:00 UTC [10]; not read end to end.

## RepoGraph (2024)

**Paper:** "RepoGraph: Enhancing AI Software Engineering with Repository-level Code Graph", Siru Ouyang, Wenhao Yu, Kaixin Ma and 6 others (9 authors in total); ICLR 2025 (arXiv comment); first version 20241003; <https://arxiv.org/abs/2410.14684> [2].

**Why fundamental:** Origin of a second design, narrowed by the same search. It offers the repository graph as a "plug-in module" that other software-engineering systems add to their own pipeline, a different design from CodexGraph's query interface [2]. The records the search returned (LingmaAgent, GraphCoder; source 13) are a full agent and a completion method, not plug-in modules, as far as their abstracts and titles show. It has 149 citations in Semantic Scholar (read 20261102 19:47 UTC, carried over), given for context [8]. Two papers cite it: Codebase-Memory (further reading) lists it among systems that build repository-level code graphs, and the AST-derived-graphs paper (further reading) calls it "aligning with the core motivation of this paper" [5][6].

**Idea:** each file is parsed with tree-sitter, lines with function calls and dependency relations are kept, and a graph links definitions to their references [4]. For a search term, RepoGraph returns the k-hop "ego-graph" around it, which is added to the prompt or offered to an agent as an action [4]. Plugged into four systems on SWE-bench Lite (RAG with BM25, Agentless, AutoCodeRover, SWE-agent), it raised the resolve rate of all four, for example Agentless with GPT-4o from 27.33% to 29.67% and SWE-agent with GPT-4o from 18.33% to 20.33%, at a higher cost (Agentless $0.34 to $0.39) [4] (first-party). It answers Aider's repository map (a blog post, Source 1), which its comparison table marks as line-level only, not file-level or repository-level [4]. The four host systems are a RAG baseline with BM25 retrieval, Agentless, AutoCodeRover and SWE-agent; it is scored on SWE-bench Lite and CrossCodeEval, which have no page here [4].

**Relations:** Answers: also: Aider repository map (a blog post, 2023).

**Read:** abstract, 20261102 20:48 UTC [2]; full text in HTML searched 20:48 to 20:53 UTC [4]; not read end to end.

## Further reading

- [Codebase-Memory](https://arxiv.org/abs/2603.27277) (2026): "Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP", Martin Vogel, Falk Meyer-Eschenbach, Severin Kohler and 2 others (5 authors in total); first version 20260328; the system paper of [codebase-memory-mcp](../projects/codebase-memory-mcp.md) (release v0.5.5 evaluated). [tree-sitter](../index/tree-sitter.md) parses 66 languages into a property graph in SQLite, served through 14 MCP tools; on 31 repositories with Claude Opus 4.6 the graph agent scored 0.83 against 0.92 for a file-reading and grep agent, with about 1,000 against 10,000 tokens and 2.3 against 4.8 tool calls a question (first-party; the first author graded the answers; the paper's own conclusion is a hybrid) [2][5]. Moved from the fundamental list: the origin it had there, the earliest to serve a graph through the [Model Context Protocol](../index/model-context-protocol.md) and measure it against a baseline, does not hold; it rested on four arXiv queries that did not return CodeCompass [12]. CodeCompass (arXiv 2602.20048, 20260223) is an MCP server exposing dependency graphs, with 258 trials on 30 tasks and graph access reaching 99.4% on hidden-dependency tasks against 76.2% for vanilla agents and 78.2% for BM25 (first-party, abstract) [14]. Codebase-Memory has no citation count, and the only later paper read that cites it is LARGER, in its related work [15].
- [AST-derived graphs](https://arxiv.org/abs/2601.08773) (2026): "Reliable Graph-RAG for Codebases: AST-Derived Graphs vs LLM-Extracted Knowledge Graphs", Manideep Reddy Chinthareddy (1 author); first version 20260113. Three pipelines answer the same questions: vector search only, a graph in which a model writes entities and dependencies per file, and a graph built by tree-sitter and walked in both directions. On Shopizer the parser graph took 2.81 seconds to build against 200.14 for the model graph, which skipped or missed 377 of 1,210 files, and cost $0.09 against $0.79; it answered 15 of 15 questions correctly and the model graph 13 of 15 (first-party; three Java projects, 15 queries each, no second annotator) [2][6]. It concludes that deterministic graphs "provide more reliable coverage and multi-hop grounding than LLM-extracted graphs at substantially lower indexing cost" [2]. Moved from the fundamental list: it was there by the catalogue's decision, no citation record is on hand, and no later paper read cites it [15].
- [Small coding agents](https://arxiv.org/abs/2610.33958) (2026): "How Do Small Coding Agents Use Code Graphs and Embeddings?", Saurav Bellam (1 author); first version 20261025. On SWE-bench Verified a localization agent gets grep only, plus embedding search, plus graph tools, or all; tasks are labelled by graph distance from the code an issue mentions to the code the fix changes. Structured tools doubled grep-only accuracy for Qwen3-8B and Gemma 4 E4B; the gain peaks at 17 to 21 points at 1.7 to 4 billion parameters and falls to 4 to 5 at 32 billion; agents chained graph expansions in 12 to 14% of episodes [2]. The label and the graph tools share one graph, favouring the graph arm at distances 0 and 1; it answers LocAgent below, whose graph arm "degrades at least as steeply as grep alone" [7]. Moved from the fundamental list: eight days old at the read, no citation count, and no later paper read cites it [15].
- [LocAgent](https://arxiv.org/abs/2503.09089) (2025): parses a codebase into a directed heterogeneous graph for multi-hop code localization; 141 citations in Semantic Scholar (read 20261102 19:47 UTC, carried over), a count that does not separate it from CodexGraph (114) and RepoGraph (149), so it is here by the catalogue's decision, not by a test of its own; the study that Small coding agents (2026) answers [8][9].
- [codebadger](https://arxiv.org/abs/2603.24837) (2026): an MCP server that gives an agent tools over a Joern code property graph (slicing, taint tracking, data flow); three use cases, no comparison with a file-reading agent (first-party, abstract); one author; arXiv comment: accepted at an ICSE 2026 workshop [11].
- [RepoAtlas](https://arxiv.org/abs/2609.16936) (2026): a training-free module that keeps evolving multimodal views of a repository graph; +2.4 points of resolve rate on SWE-bench Verified over the strongest multimodal graph baseline (first-party, abstract) [2].
- [LARGER](https://arxiv.org/abs/2605.16352) (2026): starts from lexical matches and expands a repository graph inside the agent's own search loop; +13.9 points of file-level Acc@5 on LocBench with tuned settings (first-party, abstract) [2].
