### The correction: the gateway left out OpenAI's cache-write price

The archive reports that every one of the 1,751 answers from OpenAI carried `usage.prompt_tokens_details.cache_write_tokens` beside `cached_tokens` (this page saw the field in stage A's result files). The gateway read only `cached_tokens` and priced the written tokens as plain input, USD 0.10 per million: version 1.2.0 in stage A's re-test and stages B to D, and the 1.1.0 code in stage A's first two runs (the archive infers this from the plan's file times; neither committed version contains a read of `cache_write_tokens`, which this page checked) [98][99][100][101][107][111]. The archive quotes OpenAI's prompt-caching guide: "cache writes cost 1.25× the standard, uncached input-token rate for the default 30-minute lifetime", which is USD 0.125 per million for `gpt-6-luna` on the model's page (read 20261103 by the archive's author; this page did not read OpenAI's pages) [101]. Two things show that the field was seen and the price known, and not applied:

- The plan's stage-A gate asked for the usage object to be checked for cache-write fields, and `usage_has_a_cache_write_field` is true in the result files of stage A's second attempt and of the re-test [53][99].
- Every result file of B to D records `cache_write_per_mtok` 0.125 in the run profile (read from OpenAI's pricing page 20261103 16:10), and the ledger's costs equal a recomputation at 0.10, 0.01 and 0.50 per million only, so 1.2.0 did not apply it to OpenAI's written tokens (this page's arithmetic, 16 of 16 runs) [99][104]. The archive gives the reason: the gateway applied a cache-write price only to Anthropic usage, so the price was set and unused for the whole pilot (D-39 and the plan's F1 row) [107][109]. This page's reading of the code at `a446479` agrees: the parser for OpenAI's usage returns no cache-creation count, the one for Anthropic's does [111].

The stage-A check "the gateway's cost recomputed from the tokens equals its own" used the fields the gateway read, so it was circular on this point [100][101]. So was this page's own recomputation of the 12 runs of B and C at `96d9007`: it found equality at USD 0.10, 0.01 and 0.50 and could not have found a missing write price [95]. Version 1.3.0 reads the field. The pilot was not re-run, and the ledger keeps the gateway's figures as run. The ledger cannot show the written tokens: its `cache_creation_input_tokens` is null in all 2,510 records. The counts are in `stage-totals.json`, built from response bodies that stay outside the repository [99].
