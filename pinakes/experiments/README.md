# What Pinakes has measured

Part of the [Pinakes development notes](../README.md). This page is a lab notebook: every measured
result Pinakes has published, what it decided because of it, and what it has not yet measured. It is
also the shortest honest answer to "how does Pinakes decide what to build?"

**State:** first complete pass, written 20261030 from the Pinakes documentation, read in a local
checkout of `lucagattoni/pinakes` at commit `b1bad68` (see [Sources](#6-sources)). Pinakes' own
[`STATUS.md`](https://github.com/lucagattoni/pinakes/blob/main/docs/STATUS.md) says its latest release
is 0.32.8, last reviewed 20261029 18:57 [1]. Where this page and that file disagree, that file wins.
The figures of the separate public benchmark repository are not on this page; they have [their own](datasets-benchmark.md).

Conventions for this page:

- Numbers are copied as Pinakes gives them. Pinakes sometimes writes `43 353` and sometimes
  `43,353`; this page uses commas.
- Times are as Pinakes writes them (`YYYYMMDD HH:MM`). Some of its documents say UTC explicitly (the
  20260825 18:16 decision does) [7]; the measurement sections do not. Treat them as UTC only with that caveat.
- A number the documents do not give is marked **unstated**.
- `[n]` points to the numbered source list at the end.

## 1. How Pinakes decides

The pattern is the same in every experiment below: write the test down, build the instrument, prove
the instrument can see a change, run it once, publish the number, and let the number decide. Six
rules, each in Pinakes' own words.

| # | Rule | Pinakes says | Where |
|---|---|---|---|
| 1 | **The pass criterion is fixed in writing before the number is known.** | "Criterion, fixed in advance: proceed to 2e if the vector-only leg shows strictly more rank improvements than regressions across all answerable questions. No p-value. It is deliberately loose, because its job is to stop a bump that would buy nothing — not to decide the hypothesis." Written 20260806 05:30, "before the screen has been run". For the graph channels: "A wrong number is arguable; no number is not." | [metadata plan][p-meta], [staged-gates plan][p-gates] |
| 2 | **Questions are authored blind and frozen before any code exists.** | The 110-question set "was written by authors who had not read this repository, before any injection code existed — fitting a question set to the mechanism it will judge is undetectable afterwards." The 13 multi-hop questions for the graph probe were "authored from corpus structure and frozen before the probe ran. They are not re-authored to produce failures." | [STATUS, second golden set][s-golden2], [STATUS, reachability][s-reach] |
| 3 | **Controls prove the instrument can see a change.** | A null is trusted because of "the controls, not the number: both legs proven to be the same corpus (one sha256 over all 43 353 chunk texts, equal); the injection proven to have reached the vectors (mean cosine 0.8398, zero unchanged); the uninjected index proven to still reproduce the frozen baseline 110 rows out of 110. Without the second, a silent no-op and a true null would have produced identical artifacts." The reachability probe is tested so that "a reachability probe answering 'reachable' for everything" cannot pass. | [STATUS, metadata][s-meta], [STATUS, reachability][s-reach] |
| 4 | **The cheap, reversible measurement runs before the expensive, irreversible change.** | "The measurement was deliberately sequenced before the schema change, so a schema_version bump — and a forced rebuild for every KB in existence — could not happen for an edge table whose channel might never be licensed." | [STATUS, reachability][s-reach] |
| 5 | **Results are reported even when null, and the feature ships off.** | The graph channel is "an eval-gated feature that is built, measured and off by construction, which is the structure working rather than failing." The metadata option "ships anyway, default "off", so a KB whose questions are not solved by BM25 plus a reranker can measure it rather than inherit this verdict." A withdrawn figure is withdrawn in public: "An earlier partial run published 19.0× and 16.5×. Those are withdrawn, not corrected." | [STATUS, roadmap][s-roadmap], [STATUS, metadata][s-meta], [STATUS, deep loop][s-deep] |
| 6 | **Nothing is tuned after seeing a result.** | "Nothing was tuned after seeing the number — no weight moved, no threshold revisited." The one leg that lifted anything "is reported, never gated — noticing the best-performing leg after seeing the numbers is exactly the exploratory fitting the pre-commitment forbids." | [STATUS, gate][s-gate], [ROADMAP, what it settled][r-graph] |

Two further habits sit beside these. When a headline number moves, Pinakes says why: "Twice now the
headline numbers have moved without retrieval changing. Say which it was, in the commit and here, or
the next reader credits a scorer fix to the ranker." [1]. And when a measuring tool is itself wrong,
the repair is published: one defect in the deep-loop report tool "moved the published figure from
29.75× to 4.40× at exit 0" until it was fixed [1].

## 5. Benchmarks against public datasets

A harness that runs Pinakes retrieval against public datasets that come with ground-truth evidence is
being built in a separate repository; the first dataset is MultiHop-RAG (decision D-15 in
[`DECISIONS.md`](../../DECISIONS.md)). This page will link to it once that repository is public, and
reports nothing from it until then. For what such benchmarks measure and what they miss, see
[`kb-kg/papers-benchmarks/`](../../kb-kg/papers-benchmarks/README.md).
